# Done Furniture Factory

Produce furniture people would choose because it looks good. A validator pass is not approval, a low triangle count is not a virtue by itself, and an agent-authored pile of rounded boxes is not high-class furniture.

## Non-negotiable outcome

The delivered candidate must have:

- a deliberate, original silhouette and believable construction;
- a textured GLB with base color, roughness, and normal information where the material needs it;
- recognizable material identity at room distance and in close-up;
- no baked studio lighting in base color;
- correct physical scale, grounding, front direction, and collision footprint;
- an immutable source, provenance record, audit, fixed-view review set, and explicit user verdict;
- rights that are actually compatible with the intended CC0 release.

Do not call an asset CC0 merely because it was generated by AI. Read [rights-and-sources.md](references/rights-and-sources.md) before selecting inputs or a generator.

## Start

0. Read [lessons-learned.md](references/lessons-learned.md). It lists what cost revisions on the first shipped asset, the failure catalog, and the one-shot preflight. Do this before writing a brief.
1. Read repository instructions, protected paths, renderer/catalog contracts, and the latest furniture handoff.
2. Read the approved benchmark and the most relevant rejected candidate. Extract visual facts, not just triangle counts. If none exists, say so; do not invent one.
3. Resolve one candidate brief: category, dimensions, style words, reference image(s), materials, must-keep details, forbidden defects, room context, budget, and authoring mode. Complete the **one-shot preflight** (lessons-learned section 4): rights class of the reference, dressed vs bare, part list with softness class, tile-size ratios, footprint plan, budgets.
4. Choose the route with [generation-routes.md](references/generation-routes.md). For organic or highly sculpted static furniture, the default route is **original reference image -> image-conditioned 3D -> material/geometry cleanup -> Done review**. For pieces that are mostly rigid members plus soft goods (beds, tables, cabinets, shelves, chairs with cushions), use **Route C (procedural Blender), which is proven**, see below.
5. From the repository root, create an immutable candidate directory with `node .agents/skills/done-furniture-factory/scripts/new-candidate.mjs ...`.

## Golden path for static furniture

This path is Route A (image-conditioned). Route C skips steps 1 to 5 (no hero reference, no generation credits) and follows the preflight, `blender-recipes.md`, then steps 8 to 10.

1. Create or obtain a legally clean hero reference that follows [reference-image.md](references/reference-image.md). Prefer a self-authored/generated product image on a plain background, three-quarter front view, entire object visible, no room, no props, no text/logo, diffuse light, and clear negative spaces. When the design contains important hidden structure, add consistent side/back views.
2. Spend generation credits only after showing the exact reference, provider, expected credits, privacy/licensing status, and receiving approval. Never upload an image silently.
3. Generate **one** full-quality source candidate. Preserve the provider's original/pre-remesh GLB and response metadata. Do not begin with a low-poly model.
4. Reject immediately if the silhouette, negative spaces, part count, back side, or major construction is wrong. Do not waste time texturing or polishing the wrong shape.
5. Keep a room derivative around 50k–100k triangles for ordinary hero furniture when that is what appearance needs. The observed Meshy-quality reference was about 74k triangles / 45k vertices; treat that as evidence that the previous 35k ceiling was too aggressive, not as a universal target.
6. In Blender, fix grounding, scale, normals, holes, floating fragments, fused negative spaces, and obvious intersections. Preserve separate semantic/material regions. Never replace a good generated mesh with primitive boxes just to make it easier to parameterize.
7. Replace generic or baked-looking surfaces with real physical-scale PBR materials. Prefer CC0 Poly Haven or ambientCG sets, or self-authored maps. Match grain/weave direction per part and use distinct end grain where visible.
8. Export the final GLB, run `node .agents/skills/done-furniture-factory/scripts/audit-glb.mjs <model.glb> --json <audit.json>`, and render the **final GLB**, not the Blender source.
9. Apply [review-gates.md](references/review-gates.md). Review front, three-quarter, side, back, top, underside/contact, material close-up, and a normal Done room. Use the approved benchmark in the same camera, light, exposure, and scale.
10. Ask the user for a visual verdict. Only after approval may the exact audited hash be promoted or dedicated to CC0.

For the guarded Meshy adapter, read [meshy-adapter.md](references/meshy-adapter.md). For local/open alternatives and hardware limits, read [generation-routes.md](references/generation-routes.md).

## Route C is proven (procedural Blender)

Route C shipped a high-quality asset (oak platform bed, `factory:oak-platform-bed`) and is the fastest route when the piece is mostly rigid members plus soft goods. Do not rebuild the tooling: import `scripts/blender/furniture_lib.py` (members with world-scale UVs and end grain, PBR materials, rounded slabs, cloth drape and pressure presets, creases, export), render with `scripts/blender/render-views.py` (auto-framed for any size, plus catalog thumbnail), and copy patterns from `scripts/blender/examples/oak_platform_bed.py` (rigid + cloth) or `scripts/blender/examples/plain_block_sofa.py` (newest: cylindrical legs, seg=8 corners) or `scripts/blender/examples/tufted_sage_sofa.py` (NEWEST: button tufting done as tension divots, oak base frame flush with the arms, velvet via `pile_sheen`; copy its `tufted_slab`) or `flare_arm_sofa.py` (library helpers only) or `scripts/blender/examples/beige_leather_sofa.py` (NEWEST: leather, stitched pinch seam as an inward divot, dense edge-loop cushions, thread stitches, vertex-colour tone; grain maps from `scripts/blender/make_leather_maps.py`) or `scripts/blender/examples/block_arm_sofa.py` (upholstery, parametric size + colour via CLI args; helpers `puff`, `piping`, `place_mesh`, `tinted_fabric`). Recipes and numbers: [blender-recipes.md](references/blender-recipes.md). Sofas: read [sofa-playbook.md](references/sofa-playbook.md) first. Cost/time discipline: [efficiency.md](references/efficiency.md).

**Fast loop (use it from the first draft):** `node .agents/skills/done-furniture-factory/scripts/iterate.mjs --candidate <dir> --worktree <dev worktree> --id factory-<slug>-r001 --name "<Name> (factory r001)" --stem <slug>_r001` builds the candidate, audits it (removes the old audit first), publishes it to the dev review page (GLB copy + one `FACTORY_ASSETS` line with the audited footprint, no hand edits) and screenshots it in the app viewer (`renders/app/app_front.png`; `--views front,left,right` for more). It replaces about eight hand-typed calls per revision, and the app view catches what Blender hides (black metals, dark fabric, moire). The pieces are also usable alone: `scripts/dev-publish.mjs`, `scripts/app-shot.mjs`. Upholstery helpers in `furniture_lib.py` now include `tufted_slab` (buttons as tension divots, per-button variation, buttons raycast onto the mesh), `button`, `grid_buttons`; newest example `scripts/blender/examples/grey_chaise_sectional.py` (multi-part L-shape, tufted backs, plain seats, welts, nickel legs, vertex-colour tone). **Rigid case-goods (cabinets, consoles):** copy `scripts/blender/examples/walnut_tv_console.py` (rounded shell + boolean door pocket + flush doors + veneer wrap UVs; helpers `rounded_rect_pts`, `prism`, `weighted_normals`) and read lessons-learned 7h and 7i (mesh bays as real geometry, matte black, two cabinets in parallel: `examples/black_travertine_console.py`, `examples/walnut_mesh_console.py`); doors are coplanar with the frame, never recessed. Before the first build, make a per-part feature table from the reference and state assumptions with the draft ([lessons-learned.md](references/lessons-learned.md) 7g).

Universal rules that prevent revisions (details in lessons-learned):

- **A seam, tuft or fold is a divot: it pulls the surface INWARD and never displaces anything outward** (lessons-learned 7f). Render `profile` and `side_low` views in the first draft; the owner judges the silhouette from a low side angle in the app.
- **Tiled maps must be stationary (grain only).** Random large-scale tone goes in world-noise vertex colours (`tone_setup` / `tone_apply`), never in the tile, or it repeats as a checkerboard. Print roughness mean and normal std of any CC0 sample before choosing it (smooth leather = clay).
- **Model the physical mechanism and the material's light response, not the look** (lessons-learned 7e): buttons pull fabric into divots, pile fabric needs a moderate sheen, and know what the piece stands on. Read the reference for those three before the first build.
- **A reference photo that shows a dressed piece means the asset is dressed.** Bedding, cushions, throws are parts with their own technique, not a later add-on.
- **Classify soft goods up front:** structured foam is modelled; draped textile and stuffed goods are cloth-simulated; never simulate a fold from a double layer.
- **One visible surface is one member.** Splitting a panel into several same-texture pieces makes the repeat visible in shadow.
- **A screenshot, marketplace photo or retailer image is inspiration only** in the CC0 lane. Record what is borrowed as vocabulary and what is changed.
- **Catalog footprint = audited GLB bounds** after the last geometry change; the viewer scales the larger side to it.
- **Judge colour and scale in the app viewer**, not only in Blender.
- **Self-review before showing the user** (lessons-learned section 5), and state known weak spots up front.

## Promotion

After the user's visual approval bound to the SHA-256, follow [promotion.md](references/promotion.md) (one command: `scripts/promote-candidate.mjs`): GLB and thumbnail into `public/furniture/factory/`, catalog JSON entry with footprint from the audit, `ATTRIBUTION.json`, `docs/DATA_RIGHTS.md` row, candidate records, verification. Do not commit or push unless asked; a push to `main` deploys.

## Parametric exception

Use procedural or modular asset-backed modeling only when the user needs live width/depth/module controls. Read [parametric.md](references/parametric.md). Establish an approved static visual benchmark first, then preserve it through semantic deformation or selective regeneration. Do not use parametric ambition as permission to lower the visual bar.

## Quality order

Repair in this order:

1. reference/design and silhouette;
2. proportions, construction, negative spaces, and support/contact;
3. material identity, scale, direction, and response under alternate light;
4. seams, piping, edge treatment, hardware, and medium-scale deformation;
5. topology, draw calls, texture compression, and file size.

If a problem at an earlier level remains, do not polish a later level.

## Stop conditions

- Stop after one initial build plus two diagnosed repairs.
- Stop after two candidates repeat the same defect; change the route or reference instead of retrying blindly.
- Stop for unresolved input rights, free-plan provider output that cannot be CC0, absent source GLB, missing PBR maps on a material-critical asset, or a requested upload/spend that has not been approved.
- Stop when a local generator does not fit the available hardware. Do not install a giant model or silently fall back to CPU.
- Return `BLOCKED` with the smallest decision needed. Never weaken the benchmark, hide failed views, or claim visual approval from metrics.

## Final report

Report candidate/revision, authoring route and provider/model, input and output rights, credits/cost, artifact paths and SHA-256, dimensions, vertices, triangles, primitives, materials, textures and bytes, missing PBR channels, review views, technical verdict, visual verdict, user approval, and promotion/CC0 state. State the known weak spots and what you would change with one more repair, so the user decides with the facts.

## After every asset: feed the skill

Append to [lessons-learned.md](references/lessons-learned.md) anything that cost a revision or saved one, as a rule plus a failure-catalog row, and tick or add items in its backlog. Keep the notes universal (no asset-specific numbers unless labelled as an example).
